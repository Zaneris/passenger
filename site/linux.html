Passenger on Linux

Passenger's Linux builds come from the same code as its Windows and macOS ones, and each CI run tests them on Ubuntu, then installs the archive there, debugs a program with it and uninstalls it. Fewer people use them yet, so please report anything that goes wrong.

1. What it needs

A 64-bit Intel or Arm machine with a desktop, and:

  • A .NET SDK for the projects you open, .NET 8 or later, from Microsoft's Linux packages or install script, with dotnet on your PATH (or DOTNET_ROOT naming its folder). Passenger builds and runs your projects with it, and without one says what is missing and installs one in a step once you agree. Its own language server, project host and debugger run on the .NET it carries.
  • Git, the X11 and fontconfig libraries, and a font, which most desktops already have. Passenger carries its own faces, Inter for the window and JetBrains Mono for code, and draws the characters they lack (other scripts, many symbols, emoji) in the fonts fontconfig lists. On a Wayland desktop, Passenger runs through XWayland.
  • Node.js, only for JavaScript, TypeScript, HTML, CSS, JSON, Dockerfiles and YAML (22.22.2 or later for TypeScript). Your distribution's package may be older; nodejs.org has current ones, and Settings › Node.js can name the one to use.
  • WebKitGTK 4.1, only for the HTML preview, which says so where it's missing.
# Ubuntu, Debian
sudo apt install git libx11-6 libice6 libsm6 libfontconfig1 fonts-dejavu-core

# Fedora
sudo dnf install git libX11 libICE libSM fontconfig dejavu-sans-fonts

# Arch
sudo pacman -S git libx11 libice libsm fontconfig ttf-dejavu

2. Download and unpack

arch=$(uname -m | sed 's/x86_64/x64/; s/aarch64/arm64/')
curl -LO \
    https://github.com/Zaneris/passenger/releases/latest/download/Passenger-linux-$arch.tar.gz
tar -xzf Passenger-linux-$arch.tar.gz

That makes a passenger folder. Passenger is self-contained: it can run from there as it is (./passenger/passenger), with nothing installed.

3. Install

./passenger/install.sh

For you alone, with no root needed. It copies Passenger to ~/.local/opt/passenger, links ~/.local/bin/passenger-ide, and adds Passenger to your applications menu with its icon, as one of the programs that open .sln, .slnx and .csproj files. If ~/.local/bin is not on your PATH yet, add it:

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.profile

For everyone on the machine, run it with sudo ./passenger/install.sh --system, which uses /opt/passenger, /usr/local/bin and /usr/share/applications instead.

Then open a folder or a solution from the menu, or from a shell:

passenger-ide ~/src/MySolution

The command is passenger-ide, so it never meets Phusion Passenger's passenger. An install from before it was named so has its passenger link moved to the new name; any other passenger is left as it is.

The toolbar is the window's title bar, as on Windows and macOS, with the window's buttons at its right. To have your window manager's own title bar instead, turn off Settings › Appearance › Merge main menu with window title. Under WSL and tiling window managers, the window manager's stays.

Updating

Installed with install.sh, Passenger updates itself. It downloads a newer release in the background (Help › Check for Updates asks at once), checks it against the release's SHA-256 sums, and puts it in place as it closes, or at once with Restart to Update, keeping your settings. Installed for everyone, it asks for an administrator's password where your desktop can ask, or gives you the command to run. The release it replaced is kept until the new one starts.

Run from where its archive was unpacked, Passenger only says a newer release is out, and links the archive for your machine: unpack it in its place, or install it. A copy your package manager installed is updated by it.

Packaging Passenger

A package of Passenger (an AUR, .deb or .rpm package) installs the archive's passenger folder where it chooses, with its desktop entry, icons and file types, rather than running install.sh. It also writes one file beside the app, app/package-manager: a line naming the package manager, such as pacman, apt or dnf. Passenger then leaves its updates to that manager and says so, rather than asking the system's package database whose the copy is, and never writes over the package's files. Name the command passenger-ide, as install.sh does.

echo pacman > "$pkgdir/opt/passenger-ide/app/package-manager"

Uninstalling

~/.local/opt/passenger/install.sh --uninstall
# or, if it was installed for everyone
sudo /opt/passenger/install.sh --uninstall --system

Your settings and layout stay in ~/.local/share/Passenger; delete that folder to remove them too.

If something goes wrong

  • The window does not open: run passenger-ide from a shell to see why, and check the libraries in step 1; install.sh names any of them it finds missing.
  • No font is installed, or fontconfig lists none: install.sh says so, with the command that installs one on Ubuntu, Debian, Fedora, Arch, openSUSE and Alpine, and refreshes fontconfig's cache (fc-cache -f) where it lists none of the fonts installed. Passenger says so too as it starts, and draws in the fonts it carries meanwhile.
  • C# has colour but no completion or errors: the banner over the window says why, most often that no .NET SDK installed builds the project; Install .NET SDK… installs one.
  • A TypeScript or other web file has colour but no help: the banner over it says why, most often that no Node.js was found or that it is too old for the language server.
  • Started from the applications menu, Passenger finds no dotnet or git: it takes the PATH your login shell sets, as a terminal would, so add their folders to it in your shell's profile (~/.profile, ~/.bashrc or ~/.zshrc), or set DOTNET_ROOT there.
  • Changes made outside Passenger go unseen: the inotify watches your programs share have run out. Passenger says so when it happens, with the command that raises the limit.
  • Attach to Process is refused: most distributions only let a debugger attach to its own child processes. Debugging a program Passenger starts works as it is; to attach to one it did not start, allow it until the next restart with sudo sysctl kernel.yama.ptrace_scope=0.
  • To report a problem, Help › Show Log in File Manager opens Passenger's logs, in ~/.local/share/Passenger/logs; passenger.log there says what went wrong.
