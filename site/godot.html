Godot

A free IDE for Godot 4 games in C# and GDScript

Passenger reads your C# against your scenes, shows a running game's values in your code and its nodes as they are, debugs C# and GDScript at once, and profiles both in one call tree. It works beside Godot's editor, or as its script editor. Free and open source, on Windows, macOS and Linux.

Your scenes, read with your code

The scene's tree beside its C#

A .tscn opens as Structure's tree of its nodes, each with its type and script, a row a click from its place in the file. It is marked where Godot would not load what it says, and where a signal is connected to a method its script lacks.

C# that knows its scenes

The C# of a script is checked against every scene that runs it. GetNode paths complete and are marked where no node is, and signal names, input actions, groups, animations and autoloads are completed and checked as Godot will read them. A rename of a member or a node reaches the scenes and the strings that name it.

GDScript of its own

Passenger reads GDScript with Godot's own parser and analyzer, ported: completion, types, the warnings your project.godot turns on with their fixes, Go to Declaration and Find Usages, refactorings that take a script's connections and its C# callers along, and Reformat Code by the style guide.

Shaders and resources

A .gdshader gets completion and Godot's own compiler's errors, a scene's shader too. .tres files, uids and res:// paths are read and checked, and project.godot opens as a page of its settings.

The running game, in your code

Run or debug the game and Passenger is its remote debugger, as Godot's editor is. Its C# runs under Passenger's debugger and its GDScript under Passenger's GDScript debugger, both at once, a breakpoint in either stopping it.

The live tree

The Live tree shows the game's nodes as they are, each property with its value now. Change one and the game takes it at once; Keep writes it back into the scene. The values of a script's members show after their lines as the game plays, and an error the game hits is pinned to its line.

C# changed as it runs

Hot Reload puts your C# edits in the running game, under Run too, and Godot's reload takes a GDScript saved. Run Another Copy plays several at once, for a multiplayer game.

With Godot's editor

Passenger can be Godot's script editor, opening each script at its line. Its addon has Godot's Play start a game Passenger debugs, and Open in Godot Editor selects a scene's node there.

The Game window

A game can draw in Passenger's own Game window beside its code, on Windows and on Linux under X11, taking the keys when you click it.

Tests and exports

GdUnit4, GUT and GoDotTest tests in the Unit Tests window, run and debugged. Publish exports the game with the presets of your export_presets.cfg.

For your coding agent

An agent plays the game through Passenger's MCP server: its tree, values and input, a picture of its frame, and the scenes of your open Godot editor changed as an editor's undoable actions.

One profile, GDScript and C#

Profile the game and its call tree holds both languages: its GDScript's functions as Godot's own profiler measured them, each opening at its line, beside the C# it sampled, in one scale. The Frames page charts each frame's time and opens the slowest on what it spent, its costliest function chosen, GDScript's or C#'s.

The profiler and debugger

Good to know

  • Godot 4. GDScript works with any Godot 4; C# needs Godot's .NET build, and Passenger finds it on the PATH, in Applications or where Settings names it.
  • The Game window takes Godot 4.4 or later, on Windows or Linux under X11; elsewhere the game draws in its own window.
  • Godot's own editor keeps what it holds unsaved: Passenger asks before it writes a scene open there.
