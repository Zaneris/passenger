Passenger 0.2.3 colours every language but C# far faster, with nothing native left to carry for it, and fixes what 0.2.2 left. It is still free and open source under MIT, and everything it closed is in its [0.2.3 milestone](https://github.com/Zaneris/passenger/milestone/5).

## Added

- **New Solution and New Project set a service up to run in a container or under Aspire** ([#640](https://github.com/Zaneris/passenger/issues/640)): a web, API, worker, Blazor or gRPC project can be made with a Dockerfile, the .NET SDK's container, a Docker Compose service or a place in an Aspire AppHost, its run configuration chosen so the first Run or Debug launches it that way; and one Undo takes a new project back whole.

## Faster

- **Colour for every language but C#** comes from Tint, Sébastien Ros's TextMate engine on his managed regular expressions, in place of TextMateSharp and its native Oniguruma: a full file of CSS colours about 13 times as fast and JavaScript 7 times, with a small fraction of the allocations, and no native library per system to carry or sign. Where colours differ, they now match VS Code's own tokenizer ([#572](https://github.com/Zaneris/passenger/pull/572)). Thanks to Sébastien Ros for the change.
- **A key in a long soft-wrapped line** wraps again only the rows it reaches ([#578](https://github.com/Zaneris/passenger/issues/578)): typing in the middle of a soft-wrapped line of a million characters reads about as much as in one of ten thousand, where it wrapped the whole line again at every key.
- **The Migrations window** runs fewer `dotnet ef` processes ([#465](https://github.com/Zaneris/passenger/issues/465)): Update Database after Add Migration or Remove Last Migration no longer lists the migrations and checks the model again where only that migration's files changed, the first migration is listed from Add Migration's own answer, and a build that changed nothing lists nothing again.
- **Saving on Windows** no longer holds the window ([#577](https://github.com/Zaneris/passenger/issues/577)): a file with nothing to keep but its text is put in place by a move rather than ReplaceFile, and one another program holds for a moment (a virus scanner, a build reading it) is waited out in the background, its saves landing in order, where the window stalled for up to two seconds. A build, a run, Git, a package change or an agent that follows waits for those saves, so it never reads the file as it was.
- **Run, Debug or Profile right after a Build** starts with no build ([#602](https://github.com/Zaneris/passenger/issues/602)): a Build of the solution or a project that succeeds counts as each project's last build wherever it built it as the launch would, so the launch no longer runs a `dotnet build` that compiles nothing; a Build that fails leaves nothing standing. The check of what is up to date evaluates each project once, a solution's projects side by side: 0.4 s for thirty projects where it took 3.5 to 7.
- **The first Run, Debug or test run in a folder** no longer waits up to two seconds for `dotnet --version` to exit ([#605](https://github.com/Zaneris/passenger/issues/605)): Passenger takes the SDK's version as soon as dotnet prints it, and a file-based program's project as soon as `dotnet run-api` writes it, while dotnet finishes sending its telemetry on its own.
- **An agent's own Passenger keeps the C# language server it starts ahead of its window** ([#648](https://github.com/Zaneris/passenger/issues/648)): settings the agent changes as its folder opens (solution-wide analysis, inlay hints) are given to that server, where a second server was started to load the same projects again and C#'s first answers waited for it.

## Fixed

- **The Problems window** no longer lists every problem again, and loses the row chosen, each time the open file's problems change while its Solution or Build tab is shown: a key that typed or mended an error rebuilt and sorted thousands of rows.
- **A key added to a `.resx`** whose last entry was an image or a file is written as a string, where it took that entry's type, so the IDE and the build ignored it.
- **Each kind of file gets what its kindred kinds get** ([#595](https://github.com/Zaneris/passenger/issues/595)): XAML Preview stays on or off from one window to the next, as Markdown's does; File Structure outlines JSON, YAML, CSS and TypeScript as the Structure window does; a .gitignore or .editorconfig comments a line with `#`, the .editorconfig coloured; a .slnf is coloured, folded and checked as the JSON it is; and the status bar names XAML and MSBuild files rather than XML.
- **The status bar's widgets act**: a click on the caret's place opens Go to Line, and one on the indent offers a tab or 2, 4 or 8 spaces for the file until Automatic gives it back its own.
- **Go to Related File** switches between a XAML or Razor file and its code-behind, both ways, and the active tab stays in sight however many tabs crowd the strip.
- **Every button names its keys** ([#592](https://github.com/Zaneris/passenger/issues/592)): the title bar's buttons give the keys of the keymap in force (Run (⌃F5)), and a tool window's Hide gives the keymap's own key rather than a fixed ⇧⎋.
- **An empty window says how to fill it**: the Run and Build windows before anything has run, and Find, Hierarchy, Bookmarks, Structure, Local History and the editor area with the keys of what fills them; an empty Hierarchy window no longer shows an empty bar.
- **An HTML page opens in your browser** from the Explorer's Open In, its editor's menu or Alt+F2 (Ctrl+Alt+F2 in Visual Studio's keymap off the Mac) ([#597](https://github.com/Zaneris/passenger/issues/597)).
- **A CSV, TSV or workbook table** has a right-click menu with Copy and Select All.
- **F4 or Jump to Source in a diff** opens the file at the line you're on.
- **Test actions only where a test is** ([#593](https://github.com/Zaneris/passenger/issues/593)): a console's `Main` no longer offers Run 'Main' as a test, a project without tests offers no Run Unit Tests, and the solution's row runs all its tests.
- **More menus where a file is named**: an editor tab's menu copies its path and opens it in the file manager, a terminal or (for HTML) the browser, and the Find, Hierarchy and Git log's file lists have menus that go to the file.
- **Tool windows behave alike** ([#594](https://github.com/Zaneris/passenger/issues/594)): their tabs close on a middle-click, a double-click on an editor tab gives the editors the whole window, Expand All and Collapse All sit in a tree window's header, Find works in the Run, Build, Containers and Aspire consoles, and every Refresh and the Terminal's New Session are in Find Action.
- **A program runs from where it is written** ([#596](https://github.com/Zaneris/passenger/issues/596)): a run icon beside a project's `Main` or its top-level statements, on a file-based program's first line, beside each launch profile in launchSettings.json, and on a compose file's `services:`; and Run and Debug on a program's row in the Explorer.
- **An .http or .rest file** is coloured, comments a line with `#`, and sends each request from the icon on its line, with the environment the Endpoints window would use even before that window has been opened.
- **An agent attached to Passenger stays connected through an update** on macOS, from the update after this one ([#583](https://github.com/Zaneris/passenger/issues/583)): its connection restarts from the new version in the same process and keeps its session, and a call made while Passenger restarts is answered once the new window is up. Updating to 0.2.3 itself still ends agents' connections once, since the version installed does the install. On Windows an agent still reconnects.
- **The Migrations window's first command** runs `dotnet ef` in the run's working folder, as every later one does, where it ran in the project's folder until a build had made the output folder, so a relative SQLite path named two databases.
- **C# answers follow files changed on disk** ([#604](https://github.com/Zaneris/passenger/issues/604)): Problems, solution-wide analysis, Find Usages and navigation take up files a checkout, a pull or another program changed within a moment, and no longer miss any. The language server hears of them from Passenger's own folder watcher, where its own watcher could leave some files of a large checkout stale on macOS; and a project whose restore lands while it first loads gets its packages in that window, rather than only once the folder is opened again.
- **C# answers keep coming when many files go** ([#603](https://github.com/Zaneris/passenger/issues/603)): after a checkout, or a folder deleted or cleaned, takes many C# files away, the open file's problems, highlights and navigation answer at once, and Problems drops the files' warnings within a second. The language server waited about a second for each file deleted before its next such answer, four minutes for a thousand: the project now loads again without the files before the server hears they are gone.
- **Changes made in a burst are never missed** ([#607](https://github.com/Zaneris/passenger/issues/607)): a thousand files deleted at once, a checkout, or an agent rewriting many files on a busy Mac now reach Go to File, the Explorer, the C# language server and the open files, every one. On macOS the folder's watcher heard only about half of a thousand files deleted side by side, so the rest stayed in Go to File and in the server's answers until touched again.
- **The C# language server hears every change in a burst beyond the open folder too** ([#609](https://github.com/Zaneris/passenger/issues/609)): in a project's obj and bin, the SDK's packs and NuGet's packages, a build writing many files or a script deleting a thousand reaches it file by file, and changes lost past finding reach it as deletions too. On macOS it missed up to half of such a burst, and the files' old state stayed in its answers.
- **A hint's card shows** when the pointer rests on a type or parameter name hint just as a window opens on a busy machine, or just after an .editorconfig changes ([#610](https://github.com/Zaneris/passenger/issues/610)): the C# language server, having read the project again, refused to describe the hint it had given before, and no card came until the pointer moved.
- **The mouse follows your keymap** ([#611](https://github.com/Zaneris/passenger/issues/611)): the mouse's Back and Forward buttons step back and forward anywhere in the window; Cmd+Shift-click (Ctrl+Shift-click on Windows and Linux) goes to the type's declaration and, on the Mac, Cmd+Option-click to the derived symbols; a middle click goes to the declaration in Visual Studio's keymap on Windows and Linux and in VS Code's on the Mac, where Ctrl+middle-click shows Quick Documentation; and carets and column selections take each keymap's own clicks and drags, so VS Code's Alt-click adds a caret.
- **Back and Forward on the mouse step once for every press** ([#656](https://github.com/Zaneris/passenger/issues/656)): pressed several times quickly, or right after a click, where the second and later quick presses did nothing.
- **A running program's command line no longer shows its secrets** ([#658](https://github.com/Zaneris/passenger/issues/658)): Attach to Process, Attach Profiler and an agent's `debug_state` of processes show a password, an API key or a connection string's password as dots.
- **Packages restored as a folder opens resolve in that window** ([#613](https://github.com/Zaneris/passenger/issues/613)): when a project's packages arrive during its first design-time build, or a moment before the C# language server starts on a busy machine, the server hears of them and loads the project again. It could miss them, leaving the packages unresolved until something else changed, whenever their assets file was dated more than two seconds before the server started.
- **A change of several files waits for a file another program holds** ([#614](https://github.com/Zaneris/passenger/issues/614)): on Windows, a rename, refactoring, code action or Replace in Files that writes a file a build or a virus scanner holds waits for it in the background, the status bar saying so, and says it is done only once the file has taken the change; if the program never lets go, it says it failed and why.
- **C# code under your framework's symbols is code from the moment the file opens** ([#620](https://github.com/Zaneris/passenger/issues/620)): the editor's own parse of a C# file uses the symbols its project compiles it with for the target framework the editor shows: the SDK's `NET8_0_OR_GREATER`, `NET10_0` and `WINDOWS`, and the project's own DefineConstants. Code under `#if NET8_0_OR_GREATER` was drawn disabled, with no bracket pairs or folds, until the language server's colours came; Safe Delete found nothing declared there, and a test inside it was neither listed nor run at the caret.
- **Read-only files stay as they are** ([#618](https://github.com/Zaneris/passenger/issues/618)): Save no longer writes into decompiled code, an SDK's or a package's MSBuild file, or the app's own notices. Replace in Files leaves such a file and names it as read-only, and the find bar's replace and the colour picker grey out saying why, where they said they had changed a file they never touched. Save greys on a file with nothing to save, as Save All does, and no longer rewrites an unmodified file, so the next Run doesn't build again.
- **Replace in Files is one Undo** ([#619](https://github.com/Zaneris/passenger/issues/619)): one Undo takes back every file it changed, open or closed, and one Redo makes it again; Local History keeps it as one change named for the replace, and an agent's `replace_in_files` is the same one step.
- **ESLint's fixes are no longer reported as failed** ([#622](https://github.com/Zaneris/passenger/issues/622)): ESLint was told a fix it handed the window had been refused, though the window had made it, so its server logged "Failed to apply command" after every fix.
- **Fixes and Undo wait for a file another program holds too** ([#622](https://github.com/Zaneris/passenger/issues/622)): on Windows, setting a configuration key, an Aspire parameter or a compose service's variable, XAML's own fixes, Manage User Secrets, a package's central version, a colour in another file, Safe Delete, and Undo and Redo of a change of several files wait for a held file in the background, the status bar saying so, and say they are done only once it has taken the change, or that they failed and why.
- **A Markdown preview's link written from the folder's root** (`[Guide](/docs/guide.md)`) opens that file on macOS and Linux, as it did on Windows and as images written that way were drawn ([#621](https://github.com/Zaneris/passenger/issues/621)): it was drawn as plain words.
- **A save on Linux keeps what the file had** ([#621](https://github.com/Zaneris/passenger/issues/621)): its extended attributes, its own access control list and its group (its owner too, where Passenger runs as root), as saves on macOS and Windows keep theirs. On macOS and Linux, a file another hard link also names is written in place, so the link reads what was saved; before, the other link kept the old text.
- **XAML follows a view model typed into while its project loads** ([#621](https://github.com/Zaneris/passenger/issues/621)): the text typed last always wins, where typing during the load could leave XAML with an earlier pause's types, a binding marked as missing a property just typed, until the next pause.
- **A folder moved in or out reaches the C# language server file by file** ([#625](https://github.com/Zaneris/passenger/issues/625)): a folder of sources moved, unpacked or checked out into a project or its obj, or moved away, tells the server and Go to File each file in it came or went, where they heard only the folder, so the moved files' old state stayed in the server's answers.
- **XAML, Smart Step Into and Add Aspire Orchestration read C# as your project compiles it** ([#623](https://github.com/Zaneris/passenger/issues/623)): a code-behind's handler or a view model's property under `#if NET8_0_OR_GREATER` is offered and checked in XAML, Smart Step Into offers the calls of a line under such an `#if`, and Add Aspire Orchestration finds a ServiceDefaults' extensions declared there, where XAML missed them, Smart Step Into stepped straight in and orchestration refused. Every C# file Passenger reads takes its project's LangVersion too, so a project on C# 12 reads `field` in a property as the name it compiles as.
- **The status bar keeps what an Undo, Redo or Local History revert did** while the Local History window is shown ([#624](https://github.com/Zaneris/passenger/issues/624)): "Undone: Replace 'count' with 'total'" and a revert's name were cleared as soon as they were said; the status bar's words now change only when there is something newer to say or another file is shown.
- **Closing a terminal whose program never read a paste no longer freezes Passenger** ([#653](https://github.com/Zaneris/passenger/issues/653)): closing the window or the solution while a program in the Terminal had read none of a large paste and kept writing hung the IDE for good; and closing a terminal tab no longer stops the window for a moment.
- **The terminal keeps no memory for an escape sequence of millions of parameters** ([#644](https://github.com/Zaneris/passenger/issues/644)): `cat` of a binary file no longer leaves its tab holding memory for as long as it is open (8 MiB of such output kept 128 MB); a sequence keeps its first 32 parameters and drops the rest.
- **A settings change made in another Passenger is never missed** ([#644](https://github.com/Zaneris/passenger/issues/644)): when the system drops word of it, as macOS can under load, a window reads settings.json again as it comes to the front or as its watcher says it overflowed.
- **More changes wait for a file another program holds** ([#626](https://github.com/Zaneris/passenger/issues/626)): on Windows, Add Reference, the solution's edits, Add to .gitignore, the merge window's Apply, Write and Save as Launch Profile, Add Docker Support and Compose, Add Aspire Orchestration, a publish profile, a route's request, a renamed or moved file's projects, a NuGet feed and a new project's take-out of developer tools say they are done only once the file has taken the change, or that they failed and why.
- **Change Signature updates every use or names it** ([#628](https://github.com/Zaneris/passenger/issues/628)): a call that spreads out a `params` `ReadOnlySpan<T>`, `Span<T>`, `List<T>` or `IEnumerable<T>` is changed as a `params` array's is, and a cref's parameter list follows the new signature. A method group it can't change (a delegate, an event handler, a `.Select(Parse)`), a call whose arguments it can't match and an implicit call the new signature breaks are named, with why, in the status bar and in an agent's `notApplied`, where they were left as they were while it said it was done, and the build broke. Change Signature also works on a `void` method, which it refused as having an invalid return type.
- **C# answers count a file written a moment before** ([#627](https://github.com/Zaneris/passenger/issues/627)): an agent that writes a class and its caller and at once renames the class's method, asks its usages or changes its signature has the caller renamed, counted and changed too, and Rename, Find Usages and the refactorings in the window take the same care for a file just made. A change waits, up to 10 s, for the C# language server to take in the new files of the projects it reaches, saying which file it waits for, and Find Usages answers at once, naming any such file not taken in yet. Before, the server answered for a new file as one in no project: a rename changed the declaration alone and the build broke, usages missed the caller, and a refactoring refused the file.
- **A C# load that runs long is never given up** ([#631](https://github.com/Zaneris/passenger/issues/631)): when a solution's projects take more than 5 minutes to load (a large one on a slow machine), the status bar warns that it is still loading, a click showing the log, and C# becomes ready once the load ends, solution-wide analysis, routes, Structure and usages following as for a load on time. Before, it said C# was unavailable for good, even after the projects had loaded.
- **Solution-wide analysis turned on while C# starts takes effect** ([#645](https://github.com/Zaneris/passenger/issues/645)): turned on or off in the seconds a folder takes to open, or by an agent while its Passenger is still starting, the change reaches the language server, and Problems' Solution tab lists the problems of files nobody has open, where the server went on analysing the open files alone.
- **Turning solution-wide analysis off stops it** ([#651](https://github.com/Zaneris/passenger/issues/651)): the C# language server goes back to analysing the files you have open, where it went on analysing the whole solution in the background, spending CPU and memory on problems no window listed, until the folder was opened again.
- **An agent's Passenger says when C# is slow to start** ([#645](https://github.com/Zaneris/passenger/issues/645)): started on a folder whose design-time builds take more than 5 minutes, it says C# is still starting and what it waits for, in the status bar and in the state an agent reads, and says when C# is ready, where it said "Starting C#…" all that time.
- **Evaluating `with` on a struct no longer changes the program's variable** ([#632](https://github.com/Zaneris/passenger/issues/632)): in Watch, the hover card, a breakpoint's condition or log message and an agent's `debug_evaluate`, `p with { Y = 100 }` answers the changed copy and leaves `p` as it was, and `t with { Item1 = 50 }` answers (50, "x") instead of the unchanged tuple.
- **A string joined with a char evaluates correctly** ([#632](https://github.com/Zaneris/passenger/issues/632)): `s + c`, `c + s` and `s + c + c` were garbage; a call that would keep a reference the debugger can only lend for the call is refused, saying why, and an `out` argument into the expression's own variable (`int.TryParse("5", out _)`) no longer ends the program being debugged.
- **A breakpoint, Run to Cursor and Set Next Statement on a line holding a lambda act on the line's statement** ([#659](https://github.com/Zaneris/passenger/issues/659)): a breakpoint on `var big = items.Where(i => i > 3);` stops there though the query is never read, Run to Cursor onto `int count = items.Count(i => i > 2);` stops at the count rather than inside the lambda, and Set Next Statement goes to such a line, where it refused it as another method's. A line that begins inside a lambda still stops inside it.
- **Run to Cursor stops at its line whatever breakpoint is there** ([#659](https://github.com/Zaneris/passenger/issues/659)): onto a breakpoint whose condition is false, a tracepoint, or a hit count not yet met, where the program ran on; the breakpoint keeps counting from that hit.
- **Hot Reload refuses a return-type change its callers still use** ([#660](https://github.com/Zaneris/passenger/issues/660)): a change to a method's return type or a property's type while unchanged code still calls it names the member and the call and asks for a restart, where it applied and the next call threw "Attempted to invoke a deleted method implementation".
- **After a step, Hot Reload takes a running loop to the new code from its next pass** ([#660](https://github.com/Zaneris/passenger/issues/660)), where it ran the old code a statement at a time first.
- **Pattern and out variables evaluate** ([#632](https://github.com/Zaneris/passenger/issues/632)): `o is int k && k > 40`, `x is Foo f && f.Bar > 3` and `int.TryParse(s, out int n) ? n : -1` answer as the program would, so a breakpoint whose condition uses one stops only where it holds instead of at every hit.
- **Native integers evaluate** ([#633](https://github.com/Zaneris/passenger/issues/633)): in Watch, the hover card, a breakpoint's condition or log message and an agent's `debug_evaluate`, an `nint` or `nuint` variable, arithmetic on one and a cast to one answer as the program would, and Set Value takes one, where each answered "Value does not fall within the expected range."
- **A float cast to an integer it doesn't fit evaluates as the program's runtime casts it** ([#633](https://github.com/Zaneris/passenger/issues/633)): `(int)huge` answers 2147483647 and `(uint)negOne` 0, as .NET 9 and later make them, and a cast to `byte`, `sbyte`, `short`, `ushort` or `char` follows the program's own .NET version, as .NET 11 changed it.
- **A string written in an expression works, and `new string(...)` evaluates** ([#633](https://github.com/Zaneris/passenger/issues/633)): `"abc".Length`, `"abc"[1]` and `"abc".ToUpper()` answer, where they said "Value 'String' is not a primitive CIL value", and `new string('a', 3)` answers "aaa" where it threw.
- **Array initializers evaluate** ([#647](https://github.com/Zaneris/passenger/issues/647)): `new[] { 1, 2, 3 }.Length` answers 3, a split on three or more constant chars (`s.Split('e', 'l', 'o')`) and a `u8` string work, where each said "Evaluation type token kind 'FieldDefinition' is not supported" or read the wrong memory.
- **An exception the program throws during an evaluation says its message** ([#647](https://github.com/Zaneris/passenger/issues/647)): `list[10]`, `int.Parse("x")` and `dict["zz"]` answer "Evaluation threw" with the exception's type and its message, where they gave the type alone.
- **An expression that makes a multi-dimensional array evaluates** ([#649](https://github.com/Zaneris/passenger/issues/649)): `new int[,] { {1,2},{3,4} }[1,0]` answers 3, where it failed with "TypeLoadException: The type specification does not identify a runtime type".
- **An index outside an array throws what the program would** ([#649](https://github.com/Zaneris/passenger/issues/649)): "Evaluation threw System.IndexOutOfRangeException: Index was outside the bounds of the array.", past the end, before the start, through a native integer, in a store, an array of structs or a multi-dimensional one, where it gave an internal "Value does not fall within the expected range" or an OverflowException.
- **A null array or reference in an evaluation says the program's exception** ([#652](https://github.com/Zaneris/passenger/issues/652)): `arr[0]`, `arr.Length` on a null array, and `obj.Field` or `obj.Method()` on a null reference answer "Evaluation threw System.NullReferenceException: Object reference not set to an instance of an object.", where they said "CIL execution failed …".
- **Git changes only what you chose** ([#641](https://github.com/Zaneris/passenger/issues/641)): Amend with no file chosen, in the Commit window or an agent's `vcs_commit` with `amend` and `paths: []`, changes the last commit's message alone, where it took in everything staged, a file renamed in the Explorer among it; Rollback keeps a new file Git was given to add (a `git add` in the terminal or by an agent, a merge's new file) on disk, unversioned, and says so before it acts, where it deleted it unwarned; and Unstash Changes and `vcs_stash` act on the stash chosen by its commit, so another program stashing after the list was read no longer makes Drop or Pop take a different stash.

- **Pushing a new branch goes to your remote whatever its name** ([#643](https://github.com/Zaneris/passenger/issues/643)): to the only remote, or the one you choose of several, where it assumed a remote named origin and failed.
- **A file-based program beside a solution stays one** ([#629](https://github.com/Zaneris/passenger/issues/629)): Add Reference no longer offers it, where choosing it wrote a reference no build could load; a solution filter, opened over the solution or by an agent's Passenger started on it, unloads only the solution's projects it leaves out, and the programs beside it keep their run configurations, where they were lost to Run, Build and C#; and an agent's `workspace` names the filter and marks each project not loaded.
- **What a file-based program names follows a move** ([#630](https://github.com/Zaneris/passenger/issues/630)): renaming or moving in the Explorer a folder or project a program's `#:project`, `#:include` or `#:ref` names, or the program itself, rewrites the path from the program's folder, where the program was left naming a path no longer there. A move by Cut and Paste or a drag is now one Undo, as a rename is, putting back every file that followed it.
- **A test run's answer is that run's alone** ([#634](https://github.com/Zaneris/passenger/issues/634)): an agent's `tests_run` lists the failures of the tests it ran, where a run of one passing test listed every failure the Unit Tests window still showed from earlier runs.
- **NUnit fixtures made with arguments run** ([#634](https://github.com/Zaneris/passenger/issues/634)): each instance of a `[TestFixture(1)]` `[TestFixture(2)]` or `[TestFixture(typeof(int))]` fixture is a row under its test with its own result, run from the Unit Tests window, the gutter, Run Tests at the caret and `tests_run`'s filter, and counted in the tally. Their tests were dropped as gone, never ran and never showed.
- **Containers on rootless Docker** run their .NET services as the container's root, which is you there, so an HTTPS service and user secrets work, and the run says so; rootless Podman runs them alike ([#636](https://github.com/Zaneris/passenger/issues/636)).
- **A project of several frameworks runs in a container** from its first framework's build, or the one its configuration names, where Run built every framework and then said its assembly had not been built ([#636](https://github.com/Zaneris/passenger/issues/636)).
- **`ASPNETCORE_ENVIRONMENT: development`** in any letter case counts as Development, as .NET reads it, so a container run mounts the project's user secrets and static web assets ([#636](https://github.com/Zaneris/passenger/issues/636)).
- **A container run on an engine of another machine** (an `ssh://` or `tcp://` context) opens the browser and names its address on that machine, as the Containers window's links do, where it opened localhost ([#636](https://github.com/Zaneris/passenger/issues/636)).
- **A container service whose restart failed is restarted by the next Rerun** ([#637](https://github.com/Zaneris/passenger/issues/637)): if the engine refused the restart (from a Rerun, Hot Reload or the Containers window), or a port stayed taken after every try, the service kept its old build and the next Rerun said nothing had changed.
- **Stop while a container service is made anew takes it down too** ([#637](https://github.com/Zaneris/passenger/issues/637)): Stop during a restart that recreates a service's container now waits for Compose to end and looks again, where a container the engine finished after Compose was stopped kept running, holding its ports, until Passenger closed or the next run started.
- **A service its AppHost runs as several replicas restarts** ([#638](https://github.com/Zaneris/passenger/issues/638)): Rerun after an edit, Hot Reload's restart, Debug from its start and Restart of one replica restart each replica as its own resource, where each failed with "X is not one resource of Y"; Rerun stops every replica of the project and builds it once.
- **Debug, Run without Debugger, Profile and Attach on one replica act on that replica** ([#646](https://github.com/Zaneris/passenger/issues/646)): from the Aspire window or an agent's `debug_start`, `debug_attach` and `profile`, where each could reach the replica started last; and Debug holds only that replica, so another replica's restart no longer starts it held for the debugger.
- **Two replicas of one service can be debugged at once** ([#650](https://github.com/Zaneris/passenger/issues/650)): each replica's session has a Debug tab of its own, named by its resource (`apiservice-bbbbbbbb`), where debugging the second ended the first's session. Debug or Run without Debugger on one replica says, in its menu item and the status bar, that the next run debugs (or runs) every replica, as Aspire names replicas anew each run; and an agent's `workspace` names each replica's own session.
- **The Migrations window works with a run's connection strings as written** ([#639](https://github.com/Zaneris/passenger/issues/639)): a compose run's string with an empty user name (`redis://:secret@cache:6379`) or a quoted value (`Password="a;b"`) reaches dotnet ef with only its host and port changed, where the first failed every Migrations command and the second was cut at the quoted semicolon; a string that can't be rewritten is passed as written, and the window says so.
- **Run, Debug, Profile and Hot Reload run a project where `dotnet run` runs it** ([#635](https://github.com/Zaneris/passenger/issues/635)): a launch profile that names no working folder runs in the project's `RunWorkingDirectory` (the web and worker SDKs' project folder among them), a configuration with no arguments of its own gives the program the project's `RunArguments`, and a program run from a launch profile reads its name in `DOTNET_LAUNCH_PROFILE`. Before, a program that read a file in that folder found nothing, and one that asked for its profile's name got none.
- **Aspire's Rerun restarts a service whose scoped CSS changed** ([#635](https://github.com/Zaneris/passenger/issues/635)): an edit to a component's `.razor.css` or a page's `.cshtml.css` now builds and restarts the service, and Run, Debug and Profile build first after one, where the app kept its old styles.
