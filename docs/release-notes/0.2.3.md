In Passenger 0.2.3, New Solution and New Project set a new service up to run in a container or under Aspire, Blazor WebAssembly apps run, and a C# file of top-level statements runs with no directive. It colours every language but C# far faster, with nothing native left to carry for it, and fixes some 380 bugs, among them every finding of an outside review of its code ([#740](https://github.com/Zaneris/passenger/issues/740)); its debugger now reads ref and out values, calls through generic interfaces and much more. It is still free and open source under MIT, and everything it closed is in its [0.2.3 milestone](https://github.com/Zaneris/passenger/milestone/5).

## Added

- **New Solution and New Project set a service up to run in a container or under Aspire** ([#640](https://github.com/Zaneris/passenger/issues/640)): a web, API, worker, Blazor or gRPC project comes with a Dockerfile, the SDK's container, a Compose service or a place in an AppHost, its first Run or Debug launching it that way, and one Undo takes it back whole.
- **Blazor WebAssembly apps run and debug** ([#996](https://github.com/Zaneris/passenger/issues/996)): Run and Debug start the development server the project names, as `dotnet run` does, where they failed at once; the components in the browser aren't debugged yet, and a Blazor Web App's client project is no longer a configuration of its own.
- **A C# file of top-level statements runs with no directive** ([#1006](https://github.com/Zaneris/passenger/issues/1006)): opened alone, or in a folder with no project, it is a file-based program as `dotnet run app.cs` takes it, with its configuration, completion, Run and Debug.
- **A project's Properties and a web project's wwwroot show as the folders they are** ([#699](https://github.com/Zaneris/passenger/issues/699)), with icons of their own, and Rename, Delete and Cut on them are refused saying why, where renaming one broke the app.

## Faster

- **Soft wrap in a long file costs what is on screen** ([#714](https://github.com/Zaneris/passenger/issues/714)), the rest wrapped in the background, where a 50 MB `.txt` froze the window for up to 2.5 s as it opened and a second at each step of a resize.
- **A key in a long soft-wrapped line wraps again only the rows it reaches** ([#578](https://github.com/Zaneris/passenger/issues/578)), where a line of a million characters was wrapped again at every key.
- **The Markdown preview draws only what is on screen** ([#715](https://github.com/Zaneris/passenger/issues/715)): a 600 KB CHANGELOG.md opens beside it without a 3.2 s freeze, in a tenth of the memory, and its tab comes back at once.
- **The Structure window keeps up with typing in a long file** ([#716](https://github.com/Zaneris/passenger/issues/716)): a pause in a 3 MB JSON file costs under 0.06 s where it froze the window for up to 0.6 s, and File Structure builds and filters off the window's thread.
- **Colour for every language but C# comes from Tint**, Sébastien Ros's TextMate engine on his managed regular expressions, in place of TextMateSharp and native Oniguruma ([#572](https://github.com/Zaneris/passenger/pull/572)): CSS colours about 13 times as fast and JavaScript 7 times, with a fraction of the allocations, no native library to carry or sign, and colours that match VS Code's own tokenizer. Thanks to Sébastien Ros for the change.
- **The Migrations window runs fewer `dotnet ef` processes** ([#465](https://github.com/Zaneris/passenger/issues/465)), listing nothing again where only one migration changed or a build changed nothing.
- **Saving on Windows no longer holds the window** ([#577](https://github.com/Zaneris/passenger/issues/577)): a file another program holds is waited out in the background, saves landing in order before a build, run, Git or agent reads it, where the window stalled up to two seconds.
- **Replace in Files writes the closed files it changes off the window's thread** ([#657](https://github.com/Zaneris/passenger/issues/657)), where many or large files froze the window.
- **Undo and Redo of a change across closed files read and write them off the window's thread** ([#677](https://github.com/Zaneris/passenger/issues/677)), each read once where it was read four times there.
- **A rename across the solution, Change Signature, Move, Safe Delete and fixes across files write closed files off the window's thread** ([#680](https://github.com/Zaneris/passenger/issues/680)), where each was read six times there.
- **Run, Debug or Profile right after a Build starts with no build** ([#602](https://github.com/Zaneris/passenger/issues/602)), and the up-to-date check takes 0.4 s for thirty projects where it took 3.5 to 7.
- **The first Run, Debug or test run in a folder no longer waits up to two seconds for dotnet to exit** ([#605](https://github.com/Zaneris/passenger/issues/605)): the SDK's version is taken as soon as dotnet prints it.
- **An agent's own Passenger keeps the C# language server it starts ahead of its window** ([#648](https://github.com/Zaneris/passenger/issues/648)), where a setting changed as its folder opened started a second one.
- **The branch menu opens at once however many branches there are** ([#717](https://github.com/Zaneris/passenger/issues/717)), listing the current branch, favourites and the ten committed to last, where 5,000 froze the window for 7 s.
- **XAML Preview runs a previewer only for the previews shown and the one hidden last** ([#729](https://github.com/Zaneris/passenger/issues/729)), where every XAML tab ever shown kept one (about 100 MB each).
- **A changed binary file costs Git's reads its first bytes, not its size** ([#946](https://github.com/Zaneris/passenger/issues/946)): a 100 MB asset's status and diff allocate under 5 MB where they allocated 1.2 GB.
- **Typing in a C# file of thousands of methods no longer costs about 1.5 MB at every parse** ([#1019](https://github.com/Zaneris/passenger/issues/1019)).
