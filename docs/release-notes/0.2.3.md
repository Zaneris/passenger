Passenger 0.2.3 colours every language but C# far faster, with nothing native left to carry for it, and fixes what 0.2.2 left. It is still free and open source under MIT, and everything it closed is in its [0.2.3 milestone](https://github.com/Zaneris/passenger/milestone/5).

## Faster

- **Colour for every language but C#** comes from Tint, Sébastien Ros's TextMate engine on his managed regular expressions, in place of TextMateSharp and its native Oniguruma: a full file of CSS colours about 13 times as fast and JavaScript 7 times, with a small fraction of the allocations, and no native library per system to carry or sign. Where colours differ, they now match VS Code's own tokenizer ([#572](https://github.com/Zaneris/passenger/pull/572)). Thanks to Sébastien Ros for the change.
- **A key in a long soft-wrapped line** wraps again only the rows it reaches ([#578](https://github.com/Zaneris/passenger/issues/578)): typing in the middle of a soft-wrapped line of a million characters reads about as much as in one of ten thousand, where it wrapped the whole line again at every key.
- **The Migrations window** runs fewer `dotnet ef` processes ([#465](https://github.com/Zaneris/passenger/issues/465)): Update Database after Add Migration or Remove Last Migration no longer lists the migrations and checks the model again where only that migration's files changed, the first migration is listed from Add Migration's own answer, and a build that changed nothing lists nothing again.
- **Saving on Windows** no longer holds the window ([#577](https://github.com/Zaneris/passenger/issues/577)): a file with nothing to keep but its text is put in place by a move rather than ReplaceFile, and one another program holds for a moment (a virus scanner, a build reading it) is waited out in the background, its saves landing in order, where the window stalled for up to two seconds. A build, a run, Git, a package change or an agent that follows waits for those saves, so it never reads the file as it was.
- **Run, Debug or Profile right after a Build** starts with no build ([#602](https://github.com/Zaneris/passenger/issues/602)): a Build of the solution or a project that succeeds counts as each project's last build wherever it built it as the launch would, so the launch no longer runs a `dotnet build` that compiles nothing; a Build that fails leaves nothing standing. The check of what is up to date evaluates each project once, a solution's projects side by side: 0.4 s for thirty projects where it took 3.5 to 7.
- **The first Run, Debug or test run in a folder** no longer waits up to two seconds for `dotnet --version` to exit ([#605](https://github.com/Zaneris/passenger/issues/605)): Passenger takes the SDK's version as soon as dotnet prints it, and a file-based program's project as soon as `dotnet run-api` writes it, while dotnet finishes sending its telemetry on its own.

## Fixed

- **The Problems window** no longer lists every problem again, and loses the row chosen, each time the open file's problems change while its Solution or Build tab is shown: a key that typed or mended an error rebuilt and sorted thousands of rows.
- **A key added to a `.resx`** whose last entry was an image or a file is written as a string, where it took that entry's type, so the IDE and the build ignored it.
- **Each kind of file gets what its kindred kinds get** ([#595](https://github.com/Zaneris/passenger/issues/595)): XAML Preview stays on or off from one window to the next, as Markdown's does; File Structure outlines JSON, YAML, CSS and TypeScript as the Structure window does; a .gitignore or .editorconfig comments a line with `#`, the .editorconfig coloured; a .slnf is coloured, folded and checked as the JSON it is; and the status bar names XAML and MSBuild files rather than XML.
- **The status bar's widgets act**: a click on the caret's place opens Go to Line, and one on the indent offers a tab or 2, 4 or 8 spaces for the file until Automatic gives it back its own.
- **Go to Related File** switches between a XAML or Razor file and its code-behind, both ways, and the active tab stays in sight however many tabs crowd the strip.
- **Every button names its keys** ([#592](https://github.com/Zaneris/passenger/issues/592)): the title bar's buttons give the keys of the keymap in force (Run (⌃F5)), and a tool window's Hide gives the keymap's own key rather than a fixed ⇧⎋.
- **An empty window says how to fill it**: the Run and Build windows before anything has run, and Find, Hierarchy, Bookmarks, Structure, Local History and the editor area with the keys of what fills them; an empty Hierarchy window no longer shows an empty bar.
- **An HTML page opens in your browser** from the Explorer's Open In, its editor's menu or Alt+F2 (Ctrl+Alt+F2 in Visual Studio's keymap off the Mac) ([#597](https://github.com/Zaneris/passenger/issues/597)).
- **A CSV, TSV or workbook table** has a right-click menu with Copy and Select All.
- **F4 or Jump to Source in a diff** opens the file at the line you're on.
- **Test actions only where a test is** ([#593](https://github.com/Zaneris/passenger/issues/593)): a console's `Main` no longer offers Run 'Main' as a test, a project without tests offers no Run Unit Tests, and the solution's row runs all its tests.
- **More menus where a file is named**: an editor tab's menu copies its path and opens it in the file manager, a terminal or (for HTML) the browser, and the Find, Hierarchy and Git log's file lists have menus that go to the file.
- **Tool windows behave alike** ([#594](https://github.com/Zaneris/passenger/issues/594)): their tabs close on a middle-click, a double-click on an editor tab gives the editors the whole window, Expand All and Collapse All sit in a tree window's header, Find works in the Run, Build, Containers and Aspire consoles, and every Refresh and the Terminal's New Session are in Find Action.
- **A program runs from where it is written** ([#596](https://github.com/Zaneris/passenger/issues/596)): a run icon beside a project's `Main` or its top-level statements, on a file-based program's first line, beside each launch profile in launchSettings.json, and on a compose file's `services:`; and Run and Debug on a program's row in the Explorer.
- **An .http or .rest file** is coloured, comments a line with `#`, and sends each request from the icon on its line, with the environment the Endpoints window would use even before that window has been opened.
- **An agent attached to Passenger stays connected through an update** on macOS, from the update after this one ([#583](https://github.com/Zaneris/passenger/issues/583)): its connection restarts from the new version in the same process and keeps its session, and a call made while Passenger restarts is answered once the new window is up. Updating to 0.2.3 itself still ends agents' connections once, since the version installed does the install. On Windows an agent still reconnects.
- **The Migrations window's first command** runs `dotnet ef` in the run's working folder, as every later one does, where it ran in the project's folder until a build had made the output folder, so a relative SQLite path named two databases.
- **C# answers follow files changed on disk** ([#604](https://github.com/Zaneris/passenger/issues/604)): Problems, solution-wide analysis, Find Usages and navigation take up files a checkout, a pull or another program changed within a moment, and no longer miss any. The language server hears of them from Passenger's own folder watcher, where its own watcher could leave some files of a large checkout stale on macOS.
- **C# answers keep coming when many files go** ([#603](https://github.com/Zaneris/passenger/issues/603)): after a checkout, or a folder deleted or cleaned, takes many C# files away, the open file's problems, highlights and navigation answer at once, and Problems drops the files' warnings within a second. The language server waited about a second for each file deleted before its next such answer, four minutes for a thousand: the project now loads again without the files before the server hears they are gone.
