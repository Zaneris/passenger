Passenger 0.2.3 colours every language but C# far faster, with nothing native left to carry for it, and fixes what 0.2.2 left. It is still free and open source under MIT, and everything it closed is in its [0.2.3 milestone](https://github.com/Zaneris/passenger/milestone/5).

## Added

- **A project's Properties and a web project's wwwroot show as the folders they are** ([#699](https://github.com/Zaneris/passenger/issues/699)): in the Solution view and the File System view each has an icon of its own and is listed before the project's other folders, and Rename, Delete and Cut on it are greyed in its menu and refused by keys, Find Action and an agent, saying why (ASP.NET Core serves its static files from the web root; Properties holds the launch and publish profiles), where renaming or deleting one broke the app with no word. Their files keep every action. The web root is the wwwroot of a project built by a web SDK.
- **New Solution and New Project set a service up to run in a container or under Aspire** ([#640](https://github.com/Zaneris/passenger/issues/640)): a web, API, worker, Blazor or gRPC project can be made with a Dockerfile, the .NET SDK's container, a Docker Compose service or a place in an Aspire AppHost, its run configuration chosen so the first Run or Debug launches it that way; and one Undo takes a new project back whole.

## Faster

- **Soft wrap in a long file costs the window what is on screen** ([#714](https://github.com/Zaneris/passenger/issues/714)): opening a soft-wrapped file, changing the editor's width and turning soft wrap on wrap the lines on screen at once and the rest in the background, where every line was wrapped again on the window's thread, so a 50 MB `.txt` froze it for 1.5–2.5 s as it opened and about a second at each step of a resize.
- **The Markdown preview draws only what is on screen** ([#715](https://github.com/Zaneris/passenger/issues/715)): a 600 KB CHANGELOG.md opens beside its preview without freezing the window (3.2 s before), in a tenth of the memory, and switching back to its tab is instant where it took two seconds, the preview keeping its place.
- **The Structure window keeps up with typing in a long file** ([#716](https://github.com/Zaneris/passenger/issues/716)): a pause in typing in a 3 MB JSON file with Structure shown costs the window what it does in a small one (under 0.06 s where it froze it for up to 0.6 s), and File Structure builds and filters a long outline off the window's thread.
- **Colour for every language but C#** comes from Tint, Sébastien Ros's TextMate engine on his managed regular expressions, in place of TextMateSharp and its native Oniguruma: a full file of CSS colours about 13 times as fast and JavaScript 7 times, with a small fraction of the allocations, and no native library per system to carry or sign. Where colours differ, they now match VS Code's own tokenizer ([#572](https://github.com/Zaneris/passenger/pull/572)). Thanks to Sébastien Ros for the change.
- **A key in a long soft-wrapped line** wraps again only the rows it reaches ([#578](https://github.com/Zaneris/passenger/issues/578)): typing in the middle of a soft-wrapped line of a million characters reads about as much as in one of ten thousand, where it wrapped the whole line again at every key.
- **The Migrations window** runs fewer `dotnet ef` processes ([#465](https://github.com/Zaneris/passenger/issues/465)): Update Database after Add Migration or Remove Last Migration no longer lists the migrations and checks the model again where only that migration's files changed, the first migration is listed from Add Migration's own answer, and a build that changed nothing lists nothing again.
- **Saving on Windows** no longer holds the window ([#577](https://github.com/Zaneris/passenger/issues/577)): a file with nothing to keep but its text is put in place by a move rather than ReplaceFile, and one another program holds for a moment (a virus scanner, a build reading it) is waited out in the background, its saves landing in order, where the window stalled for up to two seconds. A build, a run, Git, a package change or an agent that follows waits for those saves, so it never reads the file as it was.
- **Replace in Files** writes the closed files it changes off the window's thread ([#657](https://github.com/Zaneris/passenger/issues/657)): a replace across many or large files no longer freezes the window while it reads and writes them.
- **Undo and Redo of a change across closed files** read and write those files off the window's thread ([#677](https://github.com/Zaneris/passenger/issues/677)): taking back a Replace in Files, a rename across the solution or a Change Signature over many or large files no longer freezes the window, and each file is read once to check it, where it was read four times on the window's thread.
- **A rename across the solution, Change Signature, Move, Safe Delete and fixes across files** read and write the closed files they change off the window's thread ([#680](https://github.com/Zaneris/passenger/issues/680)): a rename touching many or large closed files no longer freezes the window, where each was read six times there.
- **Run, Debug or Profile right after a Build** starts with no build ([#602](https://github.com/Zaneris/passenger/issues/602)): a Build of the solution or a project that succeeds counts as each project's last build wherever it built it as the launch would, so the launch no longer runs a `dotnet build` that compiles nothing; a Build that fails leaves nothing standing. The check of what is up to date evaluates each project once, a solution's projects side by side: 0.4 s for thirty projects where it took 3.5 to 7.
- **The first Run, Debug or test run in a folder** no longer waits up to two seconds for `dotnet --version` to exit ([#605](https://github.com/Zaneris/passenger/issues/605)): Passenger takes the SDK's version as soon as dotnet prints it, and a file-based program's project as soon as `dotnet run-api` writes it, while dotnet finishes sending its telemetry on its own.
- **An agent's own Passenger keeps the C# language server it starts ahead of its window** ([#648](https://github.com/Zaneris/passenger/issues/648)): settings the agent changes as its folder opens (solution-wide analysis, inlay hints) are given to that server, where a second server was started to load the same projects again and C#'s first answers waited for it.

- **The branch menu opens at once however many branches the repository has** ([#717](https://github.com/Zaneris/passenger/issues/717)): it lists the current branch, your favourites and the branches committed to last, ten at most, with More Branches… taking you to the Git window's branch search for the rest, and makes a branch's own menu only as you open it, so 5,000 local branches no longer freeze the window for 7 seconds as it opens and almost a second as it closes.
- **XAML Preview runs a previewer only for the previews shown** ([#729](https://github.com/Zaneris/passenger/issues/729)) and the one hidden last, where every XAML tab ever shown kept one of its own (about 100 MB each), and a build starts again only the shown previews whose build it changed.
- **A changed binary file costs Git's reads its first bytes, not its size** ([#946](https://github.com/Zaneris/passenger/issues/946)): an agent's `vcs_status` of a changed 100 MB asset, Show Diff, Compare with Revision and a commit's diff in the log read it as it comes, where they read it whole several times over (1.2 GB allocated for one 100 MB file, now under 5 MB); a binary file open in the editor no longer reads its last-commit version at all.
