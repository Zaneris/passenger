Passenger 0.2.1 is a release of fixes and speed, and it catches up with .NET 11: file-based programs (`dotnet run app.cs`), solution filters, C# 15's unions, stepping through runtime-async code, ASP.NET Core 11's QUERY endpoints and EF Core 11's tool all work as they should. Typing, scrolling, searching, undo, the terminal, the profiler and agents' sessions do far less work, Hot Reload no longer stalls a running loop, and C#'s language server holds its memory near what it uses. It is still free and open source under MIT, it moves to .NET 11 RC3 (a security release), and everything it closed is in its [0.2.1 milestone](https://github.com/Zaneris/passenger/milestone/4).

## Faster

- **A key in the editor** colours and lays out again only the row it changed, about 80 bytes for each other row on screen where it cost 2.6 KB, and squiggles, fold chevrons, wrap signs and their pens are kept from frame to frame; a key in a line of a million characters measures only the stretch it touched, as one in a line of ten thousand does, where it measured the whole line again (39 MB a key); and a comment after a file's last brace, or a `/*` never closed, is coloured a comment however the screen asks ([#548](https://github.com/Zaneris/passenger/issues/548)).
- **Undo** keeps what each step changed rather than a version of the text for every key: 10,000 keys typed keep about 1 MB of history where they kept 17 MB, and a typed word undoes and redoes as one change ([#547](https://github.com/Zaneris/passenger/issues/547)).
- **The Find bar** searches a file where it lies, so each key typed into a search, or into a file with the Find bar open, costs the same in a file of 20,000 lines as in one of 200, where it copied the whole file for every key ([#545](https://github.com/Zaneris/passenger/issues/545)).
- **Every list reuses its rows**, the Explorer, Problems, Variables, the Git log, completion, the search popups, the profiler's and memory's views and the rest: scrolling a list of thousands costs what scrolling a short one does, and a row's icons are drawn for a fraction of what they cost ([#530](https://github.com/Zaneris/passenger/issues/530)).
- **A run starts without building** when nothing its build reads has changed, and several services of a run are built in one go ([#466](https://github.com/Zaneris/passenger/issues/466), [#467](https://github.com/Zaneris/passenger/issues/467)).
- **C# is ready sooner after a folder opens:** the project builds its language server needs are asked for as it starts, not once it is up, a second sooner for an Aspire AppHost's solution, and an agent's own Passenger (`--mcp`) opens its folder while its window is still being built, its first C# answer a second sooner ([#468](https://github.com/Zaneris/passenger/issues/468)).
- **C#'s language server** holds its memory near what it uses, about half of what it kept over a long session ([#559](https://github.com/Zaneris/passenger/issues/559)).
- **Undo and Redo of a change across files** (a rename, a refactoring, Save as Launch Profile) read again only what the change made or took away, where each rebuilt every Solution Explorer row, walked the folder again for Go to File and checked every project; Delete, New File, New Folder, Paste, a refactoring's files, Docker support, Publish's profile, a Local History revert, Unload Project and Reload Project read again only what they made, moved or took away ([#557](https://github.com/Zaneris/passenger/issues/557), [#551](https://github.com/Zaneris/passenger/issues/551)), and **with soft wrap on** a key that moves no mark leaves the error stripe as it was ([#561](https://github.com/Zaneris/passenger/issues/561)).
- **Typing above thousands of warnings** costs what it does above a few: a key no longer copies a file's whole list of problems in every language, and the error stripe no longer regroups them for each key or Enter ([#546](https://github.com/Zaneris/passenger/issues/546)).
- **Solution-wide analysis** no longer reads every warned file into the editor's text to place its warnings, and decodes each warning without a JSON document of its own: a pull over 1,000 files of 17 KB costs under 1 KB a file where it cost about 100 KB ([#552](https://github.com/Zaneris/passenger/issues/552)).
- **With solution-wide analysis on,** the open file's squiggles no longer wait for the whole project's analysis, and a burst of keys no longer has the solution analysed again for each one.
- **A file made or deleted** by another program, an agent or Git no longer has Passenger walk the whole folder again: Go to File and Find in Files take just that change, about 40 KB of work where a folder of 20,000 files cost 31 MB ([#551](https://github.com/Zaneris/passenger/issues/551)); and **a save on Windows** no longer has every project checked again and the folder walked again for Go to File, as each save over a file already there did ([#551](https://github.com/Zaneris/passenger/issues/551)).
- **Find in Files skips files that can't match** before reading them ([#533](https://github.com/Zaneris/passenger/issues/533)), **Go to File** rules most files out at once ([#535](https://github.com/Zaneris/passenger/issues/535)), and **the terminal** writes plain text in runs rather than a character at a time ([#534](https://github.com/Zaneris/passenger/issues/534)) and draws only the rows that changed, a frame of coloured output streaming by costing about a twenty-fifth of what it did ([#544](https://github.com/Zaneris/passenger/issues/544)).
- **Moving, deleting and Enter** copy nothing around each caret: Left, Right and Backspace with a thousand carets cost a fraction of what they did, Enter in a large HTML file costs what it does in a small one where it copied 30 MB, a console's links and the gutter's marks are kept from frame to frame, and the status bar's path keeps its buttons as the caret moves ([#549](https://github.com/Zaneris/passenger/issues/549), [#548](https://github.com/Zaneris/passenger/issues/548)).
- **The profiler** reads a recording in a fraction of the memory it took (Passenger's own share of a ten-second profile from about 89 MB to 6 MB), and its flame graph and timeline draw and drag without laying out every label again ([#550](https://github.com/Zaneris/passenger/issues/550)).
- **The Requests window** places each request among hundreds of routes and reads its SQL without a string for every part, a request heard among 500 routes costing what one among 5 does ([#556](https://github.com/Zaneris/passenger/issues/556)).
- **The debugger's answers, the project host's replies, test results and Aspire's logs and traces** are read where they arrive, as bytes, with no copy: a list of 2,000 variables costs under twice its own JSON where it cost four times, and a project's build reply about one and a half times where it cost fifteen; test results and Aspire's logs and traces cost under twice their JSON too ([#555](https://github.com/Zaneris/passenger/issues/555)).
- **A program's output** costs no copy of each read that nothing listens to, masking a compose run's output copies only what it masks, and the Containers window merges an AppHost's containers' logs straight into its log, about a third of what each line cost ([#554](https://github.com/Zaneris/passenger/issues/554)).
- **Saving in a repository with thousands of tags or branches** no longer reads them all again, and the Git log is read off the window's thread ([#553](https://github.com/Zaneris/passenger/issues/553)).
- **The Migrations window's commands** take about half the time: each starts EF Core's tool directly, as `dotnet ef` 10 would, instead of through `dotnet ef` and the MSBuild runs it starts for each project; on EF Core 11, a command no longer waits on `dotnet ef` and an MSBuild run for each project before EF's own tool starts ([#465](https://github.com/Zaneris/passenger/issues/465)).
- A run no longer builds again because the app wrote a file beside its project that the build doesn't copy, such as a SQLite database.

## Fixed

- **A file-based program** (`dotnet run app.cs`) opens as a project of its own, as a folder or as its file, and beside a solution too: C# across the files it `#:include`s and `#:ref`s, run configurations from its `app.run.json` (which Save and Write to Launch Profile write), its tests in the Tests window, Run, Debug, Profile and Hot Reload, and a Run that builds nothing when nothing changed, where only a single-file Aspire AppHost was known before ([#564](https://github.com/Zaneris/passenger/issues/564), [#571](https://github.com/Zaneris/passenger/issues/571)).
- **On Linux, a project or program written with its folder at once** (as `dotnet new -o` and agents write them) is found, with its run configuration, where only its folder was seen ([#571](https://github.com/Zaneris/passenger/issues/571)).
- **Hot Reload applied while the method it changes runs** goes on in the new code: a loop running the old code when the update landed could crawl on, a debugger stop at every statement, so the program seemed to hang ([#567](https://github.com/Zaneris/passenger/issues/567)).
- **Stepping through `await` in runtime-async code** (.NET 11's `<Features>runtime-async=on</Features>`, and .NET's own libraries, compiled so): Step Over stops on the method's next line once it goes on, Step Out in its awaiting caller, two runs of one method keep their steps apart, and no false "Await() returned" value is shown, where a step over an await left the method for its caller ([#562](https://github.com/Zaneris/passenger/issues/562)).
- **C# 15's unions:** a union's name is coloured where it's declared, and the debugger shows the value a union holds, typed as that value ([#563](https://github.com/Zaneris/passenger/issues/563)); **a pointer** shows its address as an `int*`, opening to what it points at, and `*p` evaluates ([#566](https://github.com/Zaneris/passenger/issues/566)).
- **A solution filter (`.slnf`)** opens its solution with the projects it names, the others unloaded and out of builds, tests and analysis, and a filter changed on disk is followed ([#565](https://github.com/Zaneris/passenger/issues/565)).
- **An HTTP QUERY endpoint** (ASP.NET Core 11's `MapMethods`) is tested and sent as a QUERY with its body, and a `.http` file keeps any method as written, where both became GET ([#568](https://github.com/Zaneris/passenger/issues/568)).
- **The Migrations window** takes its project, startup project, context and framework from EF Core 11's `.config/dotnet-ef.json` as `dotnet ef` does, and removes a migration never applied with the database unreachable ([#569](https://github.com/Zaneris/passenger/issues/569)).
- **Show Context Actions' list**, and every list Generate…, Refactor This… and the other code actions show at the caret, closes on a click away, as the completion list does, and on Escape wherever the keys are in the window; so does the inline rename box. Before, a click in the editor left the list open over the code, its fixes applying at the old place, and Escape no longer closed it ([#574](https://github.com/Zaneris/passenger/issues/574)). Thanks to pavlinyordanov for the report.
- **A build's warnings and errors** stand out in every console that shows a build, amber and red as Problems shows them, where only file links were coloured ([#570](https://github.com/Zaneris/passenger/issues/570)). Thanks to hovrawl for the report.
- **A memory snapshot** no longer writes the runtime's "[createdump] …" lines into the program's own output, which broke a program that speaks over stdio (a language or MCP server being debugged): Passenger writes the dump itself, and where Linux keeps it from doing so, it asks before letting the runtime write it ([#560](https://github.com/Zaneris/passenger/issues/560)).
- **Replace All and Replace in Files with `$_`, `` $` `` or `$'`** in the replacement work out the text they would make before making it, and refuse one past 100 million characters, saying so, where a regex matching at every place of a large file copied the whole text for each match and could take the machine's memory ([#558](https://github.com/Zaneris/passenger/issues/558)).
- **An agent's calls no longer leave open every file they read**: an agent's session over a large solution kept each one open in the IDE and the language server for as long as it ran, and a window an agent was attached to gained a tab for each file the agent read ([#559](https://github.com/Zaneris/passenger/issues/559)).
- **A C# language server that ends as it starts** is started again, as one that ends later is, and when it keeps ending the status bar says so and starts it again from its words, as the new **Restart C# Language Server** action does ([#573](https://github.com/Zaneris/passenger/issues/573)).
- **A web language server that ends as it starts** (TypeScript's, HTML's, CSS's, JSON's, YAML's, the Dockerfile server or ESLint's) is started again, as one that ends later is, and when it keeps ending its files' banners and the status bar say so and start it again from their words, where its language stayed off until the folder was opened again ([#575](https://github.com/Zaneris/passenger/issues/575)).
- **A project evaluated again while C#'s server starts** no longer has the start count as done early, where the files open went to the server before their projects loaded, each analysed alone as a Miscellaneous File, and C# said ready too soon ([#559](https://github.com/Zaneris/passenger/issues/559)).
- **A notification an Aspire AppHost sends** as it starts, such as its development certificate's, shows over the window without taking the keys, where whatever was being typed as it came, in the editor or Find Action, went to it instead.
- **A regex search on a busy machine** no longer misses matches, a search that stops says so, and Replace never changes only part of a file's matches ([#539](https://github.com/Zaneris/passenger/issues/539)).
- **The diff view's scroll bar** takes its clicks under the change markers ([#538](https://github.com/Zaneris/passenger/issues/538)), and **the Solution Explorer's scroll bar** drags without losing hold ([#528](https://github.com/Zaneris/passenger/issues/528)). Thanks to Jimmacle for both reports.
- **A folder opened on macOS through another letter case** (`cd ~/documents/dev/app`) is opened as the disk spells it, so its builds no longer delete what an earlier build wrote ([#537](https://github.com/Zaneris/passenger/issues/537)).
- **Run pressed while a build works** waits for it instead of being refused; a change to global.json's SDK versions builds again; three test rows of one name are told apart; Refresh keeps the right project's Dependencies open; and a mark no longer grows over text typed at its start ([#540](https://github.com/Zaneris/passenger/issues/540)).
- **A web project that finishes loading while its routes are read** shows its routes in Endpoints, beside its code and against its requests, where they stayed missing until one of its files was edited.
- **Run, Debug or Profile of a compose app** no longer fails now and then with "ports are not available" on a busy machine: a port Passenger chooses for a service is free at every address and outside the range the system lends its connections, and one taken anyway before the engine publishes it is chosen again.
- **A launch profile written** (by Save as Launch Profile, its Undo, or another program) no longer has the solution read again and the Solution Explorer rebuilt, and Undo or Redo in the Explorer leaves it the keys, where the next key went nowhere.
- **A folder deleted while its project builds** no longer leaves another open window's projects unloaded behind "There were problems loading project": the helper process every window shares for MSBuild is started again, and what it hadn't finished is asked of the new one.
- A container service that the debugger can't reach is never held at its start ([#517](https://github.com/Zaneris/passenger/issues/517), [#519](https://github.com/Zaneris/passenger/issues/519)), and on Linux a debugged program's exit code is no longer lost ([#478](https://github.com/Zaneris/passenger/issues/478)).

## Also new

- **Save as Launch Profile** shares a run configuration made in Passenger through its project's `launchSettings.json`, which `dotnet run` and every other IDE read ([#527](https://github.com/Zaneris/passenger/issues/527)). The idea is MangoDevx's.
