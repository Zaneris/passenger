Passenger 0.2.1 is a release of fixes and speed: long lists, searches and the terminal do far less work, a run starts without building when nothing changed, and a busy machine no longer makes a search miss matches or a project's routes go missing. It is still free and open source under MIT, it moves to .NET 11 RC3 (a security release), and everything it closed is in its [0.2.1 milestone](https://github.com/Zaneris/passenger/milestone/4).

## Faster

- **Every list reuses its rows**, the Explorer, Problems, Variables, the Git log, completion, the search popups, the profiler's and memory's views and the rest: scrolling a list of thousands costs what scrolling a short one does, and a row's icons are drawn for a fraction of what they cost ([#530](https://github.com/Zaneris/passenger/issues/530)).
- **A run starts without building** when nothing its build reads has changed, and several services of a run are built in one go ([#466](https://github.com/Zaneris/passenger/issues/466), [#467](https://github.com/Zaneris/passenger/issues/467)).
- **A file made or deleted** by another program, an agent or Git no longer has Passenger walk the whole folder again: Go to File and Find in Files take just that change, about 40 KB of work where a folder of 20,000 files cost 31 MB ([#551](https://github.com/Zaneris/passenger/issues/551)).
- **Find in Files skips files that can't match** before reading them ([#533](https://github.com/Zaneris/passenger/issues/533)), **Go to File** rules most files out at once ([#535](https://github.com/Zaneris/passenger/issues/535)), and **the terminal** writes plain text in runs rather than a character at a time ([#534](https://github.com/Zaneris/passenger/issues/534)) and draws only the rows that changed, a frame of coloured output streaming by costing about a twenty-fifth of what it did ([#544](https://github.com/Zaneris/passenger/issues/544)).
- **The profiler** reads a recording in a fraction of the memory it took (Passenger's own share of a ten-second profile from about 89 MB to 6 MB), and its flame graph and timeline draw and drag without laying out every label again ([#550](https://github.com/Zaneris/passenger/issues/550)).
- **Typing above thousands of warnings** costs what it does above a few: a key no longer copies a file's whole list of problems in every language, and the error stripe no longer regroups them for each key or Enter ([#546](https://github.com/Zaneris/passenger/issues/546)).
- **The Find bar** searches a file where it lies, so each key typed into a search, or into a file with the Find bar open, costs the same in a file of 20,000 lines as in one of 200, where it copied the whole file for every key ([#545](https://github.com/Zaneris/passenger/issues/545)).
- **A program's output** costs no copy of each read that nothing listens to, masking a compose run's output copies only what it masks, and the Containers window merges an AppHost's containers' logs straight into its log, about a third of what each line cost ([#554](https://github.com/Zaneris/passenger/issues/554)).
- **Undo** keeps what each step changed rather than a version of the text for every key: 10,000 keys typed keep about 1 MB of history where they kept 17 MB, and a typed word undoes and redoes as one change ([#547](https://github.com/Zaneris/passenger/issues/547)).
- **Saving in a repository with thousands of tags or branches** no longer reads them all again, and the Git log is read off the window's thread ([#553](https://github.com/Zaneris/passenger/issues/553)).
- **With solution-wide analysis on,** the open file's squiggles no longer wait for the whole project's analysis, and a burst of keys no longer has the solution analysed again for each one.
- **The Migrations window's commands** take about half the time: each starts EF Core's tool directly, as `dotnet ef` 10 would, instead of through `dotnet ef` and the MSBuild runs it starts for each project ([#465](https://github.com/Zaneris/passenger/issues/465)).
- A run no longer builds again because the app wrote a file beside its project that the build doesn't copy, such as a SQLite database.

## Fixed

- **Replace All and Replace in Files with `$_`, `` $` `` or `$'`** in the replacement work out the text they would make before making it, and refuse one past 100 million characters, saying so, where a regex matching at every place of a large file copied the whole text for each match and could take the machine's memory ([#558](https://github.com/Zaneris/passenger/issues/558)).
- **An HTTP QUERY endpoint** (ASP.NET Core 11's `MapMethods`) is tested and sent as a QUERY with its body, and a `.http` file keeps any method as written, where both became GET ([#568](https://github.com/Zaneris/passenger/issues/568)).
- **C# 15's unions:** a union's name is coloured where it's declared, and the debugger shows the value a union holds, typed as that value ([#563](https://github.com/Zaneris/passenger/issues/563)); **a pointer** shows its address as an `int*`, opening to what it points at, and `*p` evaluates ([#566](https://github.com/Zaneris/passenger/issues/566)).
- **A file-based program** (`dotnet run app.cs`) opens as a project of its own, as a folder or as its file: C# across the files it `#:include`s and `#:ref`s, run configurations from its `app.run.json`, and Run, Debug, Profile and Hot Reload, where only a single-file Aspire AppHost was known before ([#564](https://github.com/Zaneris/passenger/issues/564)).
- **A regex search on a busy machine** no longer misses matches, a search that stops says so, and Replace never changes only part of a file's matches ([#539](https://github.com/Zaneris/passenger/issues/539)).
- **The diff view's scroll bar** takes its clicks under the change markers ([#538](https://github.com/Zaneris/passenger/issues/538)), and **the Solution Explorer's scroll bar** drags without losing hold ([#528](https://github.com/Zaneris/passenger/issues/528)). Thanks to Jimmacle for both reports.
- **A folder opened on macOS through another letter case** (`cd ~/documents/dev/app`) is opened as the disk spells it, so its builds no longer delete what an earlier build wrote ([#537](https://github.com/Zaneris/passenger/issues/537)).
- **Run pressed while a build works** waits for it instead of being refused; a change to global.json's SDK versions builds again; three test rows of one name are told apart; Refresh keeps the right project's Dependencies open; and a mark no longer grows over text typed at its start ([#540](https://github.com/Zaneris/passenger/issues/540)).
- **A web project that finishes loading while its routes are read** shows its routes in Endpoints, beside its code and against its requests, where they stayed missing until one of its files was edited.
- **Run, Debug or Profile of a compose app** no longer fails now and then with "ports are not available" on a busy machine: a port Passenger chooses for a service is free at every address and outside the range the system lends its connections, and one taken anyway before the engine publishes it is chosen again.
- **A launch profile written** (by Save as Launch Profile, its Undo, or another program) no longer has the solution read again and the Solution Explorer rebuilt, and Undo or Redo in the Explorer leaves it the keys, where the next key went nowhere.
- **An agent's calls no longer leave open every file they read**: an agent's session over a large solution kept each one open in the IDE and the language server for as long as it ran, and a window an agent was attached to gained a tab for each file the agent read ([#559](https://github.com/Zaneris/passenger/issues/559)).
- **Hot Reload applied while the method it changes runs** goes on in the new code: a loop running the old code when the update landed could crawl on, a debugger stop at every statement, so the program seemed to hang ([#567](https://github.com/Zaneris/passenger/issues/567)).
- **A folder deleted while its project builds** no longer leaves another open window's projects unloaded behind "There were problems loading project": the helper process every window shares for MSBuild is started again, and what it hadn't finished is asked of the new one.
- A container service that the debugger can't reach is never held at its start ([#517](https://github.com/Zaneris/passenger/issues/517), [#519](https://github.com/Zaneris/passenger/issues/519)), and on Linux a debugged program's exit code is no longer lost ([#478](https://github.com/Zaneris/passenger/issues/478)).

## Also new

- **Save as Launch Profile** shares a run configuration made in Passenger through its project's `launchSettings.json`, which `dotnet run` and every other IDE read ([#527](https://github.com/Zaneris/passenger/issues/527)). The idea is MangoDevx's.
