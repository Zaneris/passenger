Passenger 0.3.3 fixes three things you could run into on 0.3.2. On Windows, a Git sign-in could leave a clone, push or fetch waiting for good, and installing a missing .NET SDK into your own folder could fail partway. On every system, Format Document missed an `.editorconfig` you add beside your solution. It also lets go of closed windows it kept in memory, and keeps the C# language server up to date with your project's files while it reads the SDK's own folders. It is still free and open source under MIT, and everything it closed is in its [0.3.3 milestone](https://github.com/Zaneris/passenger/milestone/11).

## Fixed

- **A Git sign-in on Windows no longer waits for good** ([#1455](https://github.com/Zaneris/passenger/issues/1455)): a clone, push or fetch that asked for a login, or a signed commit whose key asked for its passphrase, could wait forever once you answered. Git asks through Passenger, and on Windows the end of the question or of your answer sometimes never reached the other side. Each now ends with a mark of its own. On a test machine that 0.3.2 hung on within 94 clones, 1,000 went through.
- **Installing a missing .NET SDK into your own folder works on Windows when something reads it as it moves in** ([#1470](https://github.com/Zaneris/passenger/issues/1470)): a virus scan reaching the newly unpacked SDK made Windows refuse to move it, which Passenger took for a move to another drive. It then copied the SDK instead and failed at the end. It now waits for whatever holds the folder to let go, and says what it is.
- **Format Document follows an `.editorconfig` added beside your solution** ([#1459](https://github.com/Zaneris/passenger/issues/1459)): an `.editorconfig` added or removed in a folder above a project's own reached the C# language server only once something else had the project load again. So braces came out on their own lines where you asked for them on the same line. Now the project loads again as soon as one comes or goes.

## Lighter as you work

- **Closed windows are let go** ([#1445](https://github.com/Zaneris/passenger/issues/1445)): a window closed while the C# language server was still loading its first projects stayed in memory for up to five minutes. A window in which an agent first looked at Passenger's own windows stayed until Passenger quit.
- **Your project's changes reach C# while the SDK's folders are still being read** ([#1467](https://github.com/Zaneris/passenger/issues/1467)): on Windows, the C# language server's first look at the SDK's packs and reference assemblies can take minutes on a cold disk. Until it ended, the server wasn't told about changes to your own files, such as a source generator's output in `obj`. Each folder now tells the server on its own, and those large folders are read once rather than twice.
