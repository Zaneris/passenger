Passenger 0.3.2 runs on .NET 11 as Microsoft released it, where 0.3.1 ran on its release candidate, and says in one place what it does for .NET 11 and C# 15: [in the README](https://github.com/Zaneris/passenger#net-11-and-c-15) and [on passenger-ide.net](https://passenger-ide.net/#dotnet11). It also brings back a nested project's global usings and generated code to C# without reopening the folder, keeps a refactoring asked just after a file was deleted outside Passenger from failing partway, and makes typing in very large C# and project files lighter. It is still free and open source under MIT, and everything it closed is in its [0.3.2 milestone](https://github.com/Zaneris/passenger/milestone/10).

## Highlights

- **Built on .NET 11 as released**: Passenger carries its own copy of the .NET 11 runtime, now the released one, so nothing on your machine changes; your projects can target .NET 8 or later, and opening a .NET 11 project without its SDK offers to install it into your own folder.
- **What Passenger does for .NET 11, in one place** ([.NET 11 and C# 15](https://github.com/Zaneris/passenger#net-11-and-c-15)): C# 15's unions coloured where you declare them and shown in the debugger as the value they hold, runtime async stepped as you wrote it with Step Out showing the value returned, live metrics and the Requests window from a .NET 11 program's start, EF Core 11's `dotnet ef` in the Migrations window, and a project built for .NET 10 and 11 tested under each.
- **A nested project's global usings and generated code reach C# again** ([#1433](https://github.com/Zaneris/passenger/issues/1433)): in a folder with a project at its top and others below it, a global using added to a project below, its generated editorconfig and a source generator's output took effect only once the folder was opened again under the C# language server 0.3.1 carries. They now take effect as the build writes them.
- **A refactoring just after a file was deleted outside Passenger** ([#1444](https://github.com/Zaneris/passenger/issues/1444)): a rename or other refactoring asked right after `git rm` or a checkout removed a file could fail partway at that file on a busy machine. It now waits for the C# language server to let go of the deleted file and works the change out again, or refuses before writing anything.

## Fixed

- **Windows no longer refuses deleting, renaming or moving a project's folder** just as the C# language server starts ([#1433](https://github.com/Zaneris/passenger/issues/1433)).
- **A container's .NET service chosen before its program is up says so under Stats** and looks again until it is reached, where its metrics stayed empty with nothing said ([#1436](https://github.com/Zaneris/passenger/issues/1436)).
- **The Stats tab and the Requests window let go of a program at once** when stopped, hidden, closed or switched to another, where they waited out a runtime that takes no session, 10 seconds or more, and then asked it again ([#1442](https://github.com/Zaneris/passenger/issues/1442)).
- **A Markdown heading after a lone carriage return** (text pasted from an old Mac file) is found on its own line from Structure, File Structure and an agent's outline, where choosing it put the caret lines below it, and the outline of such a file no longer fails ([#1429](https://github.com/Zaneris/passenger/issues/1429)).

## Lighter as you work

- **Typing in a C# file of thousands of warnings** ([#1427](https://github.com/Zaneris/passenger/issues/1427)): each pause keeps the diagnostics that didn't change, and Problems' File tab lists again only what did, where every pause made all of them again on the window's thread: about 176 bytes a warning where it cost 1,836.
- **Typing in a large project file** ([#1427](https://github.com/Zaneris/passenger/issues/1427)): a pause no longer copies and parses the file on the window's thread. In a project file of 4,000 items a pause costs that thread 77 KB, where it cost 5.3 MB.
- **Language servers' messages cost less than half the memory** ([#1429](https://github.com/Zaneris/passenger/issues/1429)): every conversation Passenger has over JSON-RPC (each language server, the Testing Platform's test hosts, an AppHost) reads a message's contents straight into what asks for them. On the same editing session, reading them allocated about 16 MB, where it allocated 37 to 41 MB.
- **A Markdown file's outline reads only what changed** and shares the preview's read ([#1429](https://github.com/Zaneris/passenger/issues/1429)): a 70 KB file costs 353 KB a change where it cost 1.2 MB, and a 1 MB file 555 KB where it cost 18.7 MB.
- **Less held while a folder is open** ([#1428](https://github.com/Zaneris/passenger/issues/1428)): the Welcome screen is let go of until it shows again (683 KB on Passenger's own solution), and the search for single-file Aspire AppHosts keeps only what it found (82 KB where it kept 983 KB). Each key and caret move also allocates a little less on the window's thread ([#1427](https://github.com/Zaneris/passenger/issues/1427)).
